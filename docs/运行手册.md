# EMS 运行手册（V2 数据库版）

面向"把项目跑起来"和"跑出问题时怎么查"的实操文档。V2 指 `main` 分支 / `v2` 标签：**EMS 与 Web 后端通过同一个 SQLite 文件交换数据，不使用 MQTT**。

---

## 1. 一图看懂

```text
下端设备 ⇄ Modbus TCP/RTU ⇄ EMS ──写 realtime / 读 commands──► SQLite ◄── 写 commands / 读 realtime ── Web 后端 ⇄ HTTP+WebSocket ⇄ 浏览器
```

- EMS 每秒把当前值写入 `realtime` 表，按周期把正常值采样进 `history`。
- 后端从 `realtime` 读值，经 WebSocket 推给页面；趋势从 `history` 查。
- 页面提交控制 → 后端校验后写 `commands` 表 → EMS 认领执行 → 回写 `done/failed`。

**两个进程必须指向同一个 `--db` 文件，否则页面永远无数据。**

## 3. 启动

### 3.1 推荐：一键脚本

```bash
./dev-up.sh
```

输出示例：

```text
🚀 已启动 EMS（config/simulator，库 data/ems-v2.db），日志 logs/v2/ems.log
🚀 已启动 Web 后端，日志 logs/v2/web.log
⏳ 等待后端与实时数据就绪...
connected=True control_enabled=True last_error=''
  simEm.PccPower         YC value=500.0 quality=1
  ...
页面:     http://127.0.0.1:8080
WebSocket: ws://127.0.0.1:8081
控制令牌: 58f97749...
停止:     ./dev-down.sh
```

浏览器打开 `http://<机器IP>:8080`，把「控制令牌」填进页面输入框 → 点「验证并解锁」→ 控制按钮才可用。

### 3.2 手动启动（两个终端）

**终端 A —— EMS**

```bash
cd /mnt/d/CodeFiles/Codex/EMS/ems/EMS_Demo
./build/ems_gateway --config config/simulator --db data/ems-v2.db --history-interval-sec 60
```

**终端 B —— Web 后端**

```bash
cd /mnt/d/CodeFiles/Codex/EMS/ems/EMS_Demo
./.venv/bin/python web_backend/server.py \
  --config config/simulator --db data/ems-v2.db \
  --bind 0.0.0.0 --port 8080 --ws-bind 0.0.0.0 --ws-port 8081 \
  --control-token "$(cat logs/v2/token 2>/dev/null || openssl rand -hex 32)"
```

> ⚠️ `dev-up.sh` 与手动启动**只能选一种**。同时运行会出现端口冲突和双写同一数据库。

## 4. 停止

```bash
./dev-down.sh
```

```bash
pkill -f 'build/ems_gateway'
```

## 5. 令牌（控制开关）

| 事项 | 说明 |
|---|---|
| 存储位置 | `logs/v2/token`（`dev-up.sh` 自动生成，权限 600） |
| 查看 | `cat logs/v2/token; echo` |
| 重新生成 | `openssl rand -hex 32 > logs/v2/token`，然后重启后端 |
| 手动指定 | `--control-token "xxx"` 或环境变量 `EMS_WEB_CONTROL_TOKEN` |
| 未配置时 | 后端返回 503「后端未配置控制令牌，控制接口已关闭」，页面按钮全灰 |
| 页面行为 | 令牌只存在 JS 变量里，**刷新页面要重新输入** |

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `OSError: [Errno 98] Address already in use ('0.0.0.0', 8081)` / `RuntimeError: WebSocket 服务无法启动` | 已有一个后端在跑，占着 8081 | `./dev-down.sh`；或 `fuser -k 8081/tcp 8080/tcp`；确认 `ss -ltnp \| grep -E ':808[01]'` 为空再启动 |
| 页面显示「EMS 通信异常」/ `connected=false` | EMS 没跑、或 EMS 与后端 `--db` 指向不同文件、或库里长时间没新值 | 查 `logs/v2/ems.log` 是否有采集日志；核对两边 `--db` 完全一致 |
| 页面「后端未配置控制令牌，控制已关闭」 | 后端启动时没给令牌 | 用 `--control-token` 或 `EMS_WEB_CONTROL_TOKEN` 重启后端 |
| 控制返回 409「EMS 实时链路未连接」 | `connected=false` | 先解决上一条 |
| 控制返回 409「联锁未满足」 | 反馈点质量差或值不等于期望值 | 页面控制卡会提示具体点位；等设备状态满足后再下发 |
| 历史查询 503 / 空图 | 库文件不存在、或 `history` 表结构与 EMS 写入不一致 | 确认用的是新建的 `data/ems-v2.db`（V2 的 `history` 有 `quality` 列，V1 的库没有） |
| `sqlite3.OperationalError: no such column: quality` | 用 V1 的旧库跑 V2 | 换库：`--db data/ems-v2.db`，或删掉旧库重跑 |
| EMS 启动报「点表为空，退出」 | `--config` 指错目录 | V2 用 `--config config/simulator` |
| 设备全 `quality=0` | 仿真器未启动或 IP 不通 | 确认 `172.22.240.1:1500/1501/1601` 可连（`config/simulator/devices.conf`） |

## 8. 日志

| 文件 | 内容 |
|---|---|
| `logs/v2/ems.log` | EMS 采集、命令执行、错误 |
| `logs/v2/web.log` | 后端启动、HTTP/WS 监听、接口错误 |
| `logs/ems.log` | EMS 全局日志（含启动配置、历史存储） |
| `logs/DeviceN.log` | 第 N 台设备的连接与轮询明细 |

实时跟随：

```bash
tail -f logs/v2/ems.log logs/v2/web.log
```

## 9. 数据与清理

| 数据 | 位置 | 说明 |
|---|---|---|
| 实时值/历史/命令 | `data/ems-v2.db` | 删掉即从零开始（EMS 会自动建表） |
| 运行日志 | `logs/` | 可随时删 |
| 令牌 | `logs/v2/token` | 删掉后 `dev-up.sh` 会重新生成 |

彻底重置：

```bash
./dev-down.sh
rm -f data/ems-v2.db*
./dev-up.sh
```

## 10. 版本切换（V1 MQTT 版 ⇄ V2 数据库版）

两个版本的数据库结构不同，**不要共用同一个库文件**。

| | V1 | V2 |
|---|---|---|
| 分支 | `v1-mqtt` | `main` |
| 标签 | `v1` | `v2` |
| 传输 | MQTT Broker | 共享 SQLite |
| 数据库 | `data/ems.db` | `data/ems-v2.db` |
| 启动 | `./dev-up.sh`（会起 Broker 或复用） | `./dev-up.sh`（不起 Broker） |
| 需要 MQTT | 是（127.0.0.1:1883） | 否 |

切换步骤（**切完必须重编译**，`build/` 不在 git 里）：

```bash
./dev-down.sh
git switch v1-mqtt      # 或 git switch main
./build.sh
./dev-up.sh
```
